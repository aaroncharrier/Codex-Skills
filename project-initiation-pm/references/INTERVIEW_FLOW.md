# Interview Flow

## 1. Read First

If the user references documents, read them before asking questions.

Use the documents to:
- reduce redundant questions
- identify missing facts
- identify contradictions
- target the next 3 questions

## 2. Intake

Capture:
- what triggered the request
- what business problem exists
- who needs the outcome
- what type of project this appears to be

## 3. Classification

Choose the primary branch and ask for confirmation before proceeding deeply.

## 4. Branch Discovery

Use the branch-specific question bank.
Ask exactly 3 questions at a time.

## 5. Adjacent Scope Validation

Always check for:
- upstream dependencies
- semantic-layer work
- reporting impact
- metric-definition work
- DQ or reconciliation needs
- operational support needs
- security or governance implications

## 6. Delivery Planning

Capture enough detail to make the project actionable:
- timeline
- dependencies
- blockers
- phases or major tasks
- acceptance criteria
- rollout or release needs

## 7. Stop Condition

Stop when:
- a credible first draft exists
- remaining unknowns can be marked `TBD`
- additional questions are no longer adding material value
