# Project Plan Population Rules

## General Rules

- Populate what is known.
- Mark unknown required items as `TBD`.
- Prefer clear partial content over blank sections.
- Do not invent owners, dates, or thresholds.
- Use `docs/PROJECT_PLAN.md` as the main source of truth.

## Populate Early

- Document Control
- Objective
- Business Context
- In Scope
- Out of Scope
- Assumptions
- Constraints
- Current State
- Target State
- Initial dependencies and risks
- High-level success criteria

## Populate Mid-Interview

- Architecture Overview
- Data sources and destinations
- Phase Summary
- Milestone Tracker
- Deliverables
- Data Quality Plan
- Tooling / Environment Needs

## Populate Late or Leave `TBD`

- KPI baselines
- KPI targets
- exact milestone dates
- named approvers
- rollout dates
- rollback trigger details
- alert recipients
- precise thresholds

## Supporting Files

### `docs/OPEN_QUESTIONS_AND_DECISIONS_LOG.md`
Use for:
- unresolved questions
- pending architecture choices
- approvals needed
- meaningful decisions made during intake

### `docs/WORK_LOG.md`
Keep light at startup.
Record only:
- startup steps completed
- confirmed discoveries worth preserving
- meaningful drafting actions when useful
