# Tutorial Structure

Use this delivery pattern for every quest.

## Teaching cadence

1. Start with a short mission briefing.
2. Explain the concept in plain language.
3. Move through staged build steps.
4. Add checkpoints after meaningful progress points.
5. Include troubleshooting notes when likely failure points exist.
6. End with a visible next quest or next step.

Alternate action and explanation instead of giving one long lecture or one large code dump.

## Required output order

1. Quest title
2. Mission briefing
3. Why this quest matters
4. Quest classification
5. Build stages
6. Checkpoints
7. Acceptance criteria
8. Stretch goals
9. Evidence to bring back
10. Quest-wiki updates
11. Next quest

## Style rules

- Keep NPC flavor light and practical.
- Favor compact checklists over repeated prose.
- Keep the learner in control of the code and decisions.
- Make the next action obvious.
