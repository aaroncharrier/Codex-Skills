# Open Questions and Decisions Log Completion Questionnaire

Use this questionnaire to gather the inputs needed to start or refresh an open questions and decisions log for a data analytics project. Answer briefly and concretely. If an answer is unknown, write `TBD` and name the owner who will resolve it.

## Document Header
- Project name:
- Document owner:
- Review cadence:
- Version / status:
- Effective date:
- Related BRD / PRD / SRD / other links:

## 1. Decision-Making Scope
1. What project, release, or workstream does this log cover?
2. Which teams should use this as the source of truth for unresolved decisions?
3. What kinds of items belong here: scope, source contracts, ownership, metric definitions, release decisions?
4. What kinds of items should stay out of this log?

## 2. Current Open Questions
1. What important questions are still unresolved?
2. Why does each question matter to scope, trust, delivery, or release?
3. Is there a current working assumption for each question?
4. Who owns resolving each question?
5. By what date must each question be resolved?

## 3. Existing Approved Decisions
1. Which major project decisions have already been made?
2. What exactly was decided in each case?
3. Why was that decision made?
4. Who approved it?
5. Which documents, datasets, or releases are affected by it?

## 4. Assumptions That Need Validation
1. What assumptions are teams currently making about data arrival, scope, mappings, ownership, or SLAs?
2. Which assumptions are safe for now, and which are high risk?
3. How will each assumption be validated?
4. Who owns validation, and by what date?
5. What happens if the assumption is false?

## 5. Follow-Up Actions
1. What actions are required to answer the current open questions?
2. Which actions need cross-team coordination or escalation?
3. Who owns each follow-up action?
4. What due date should be attached to each action?
5. Which actions are already underway?

## 6. Review and Escalation
1. How often should this log be reviewed?
2. In which forum should it be reviewed: standup, design review, steering committee, go-live readiness?
3. What types of unresolved items require escalation?
4. Who is the escalation path for scope, source, metric, or release disputes?

## Final Check
1. Which open items could change project scope or release timing?
2. Which open items block BRD, PRD, SRD, or go-live approval?
3. Who owns each blocking item, and by what date?
